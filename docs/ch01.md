# 第 1 课 · 实例与扩展

> 对应源码：`lessons/01_instance.cpp`
> 目标：建立应用程序与 Vulkan 库的连接，理解"扩展"这个贯穿全教程的概念。

## 1.1 Vulkan 的第一道门：实例

一切从 `VkInstance` 开始。可以把它理解为**应用与 Vulkan 库之间的"会话"**：

- 进程与 Vulkan 加载器（loader）建立连接
- 声明应用的基本信息和要启用的功能模块
- 之后所有 API 调用都在这个实例的上下文里进行

```cpp
VkApplicationInfo appInfo{};                       // 元数据：名字/版本（可省略，但建议填）
appInfo.sType = VK_STRUCTURE_TYPE_APPLICATION_INFO;
appInfo.pApplicationName = "Hello Triangle";
appInfo.applicationVersion = VK_MAKE_VERSION(1, 0, 0);
appInfo.apiVersion = VK_API_VERSION_1_0;

VkInstanceCreateInfo createInfo{};                 // 主参数结构
createInfo.sType = VK_STRUCTURE_TYPE_INSTANCE_CREATE_INFO;
createInfo.pApplicationInfo = &appInfo;
```

注意两个结构的分工：`VkApplicationInfo` 是**可选的自我介绍**，`VkInstanceCreateInfo` 才是真正的参数表。Vulkan 里几乎所有创建函数都是这个套路：一个 `sType` 标明结构类型 + 若干参数字段。

## 1.2 扩展：Vulkan 的"可选功能模块"

Vulkan 核心 API 之外的功能（尤其是和操作系统打交道的能力）都以**扩展**形式存在。创建窗口相关的实例扩展就是典型——它们把渲染结果接到 Windows 的窗口系统上。

关键洞察：**你不需要背扩展清单，GLFW 会亲口告诉你**。

```cpp
uint32_t glfwExtensionCount = 0;
const char** glfwExtensions;
glfwExtensions = glfwGetRequiredInstanceExtensions(&glfwExtensionCount);

createInfo.enabledExtensionCount = glfwExtensionCount;
createInfo.ppEnabledExtensionNames = glfwExtensions;
createInfo.enabledLayerCount = 0;
```

这段代码做了三件事：问 GLFW"窗口系统需要哪些扩展"、把清单原样转交给 Vulkan、暂不启用任何层（第 2 课再装"体检医生"）。

## 1.3 两段式枚举：Vulkan C API 的通用模式

想检查本机到底支持哪些扩展，会遇到 Vulkan 的标志性模式——**先问数量，再取数据**：

```cpp
uint32_t extensionCount = 0;
vkEnumerateInstanceExtensionProperties(nullptr, &extensionCount, nullptr);  // ① 只要数量
std::vector<VkExtensionProperties> extensions(extensionCount);
vkEnumerateInstanceExtensionProperties(nullptr, &extensionCount, extensions.data());  // ② 填满数组
```

为什么这样设计？Vulkan 是 C API，调用方负责内存。一次调用告诉你"要准备多大的容器"，二次调用才真正取货。这个模式会在第 3、5、6 课反复出现。

## 1.4 动手改：扩展可用性检查

把 GLFW 的需求清单和本机扩展全集做一次核对，缺什么指名道姓报出来：

```cpp
// 需求清单 ⊆ 全集 ？
for (const char* required : requiredExtensions) {
    bool found = std::any_of(extensions.begin(), extensions.end(),
        [&](const VkExtensionProperties& e) {
            return std::strcmp(e.extensionName, required) == 0;
        });
    if (!found) throw std::runtime_error(std::string("缺少实例扩展: ") + required);
}
```

`"遍历需求清单、查全集"`这个模式后面还会用到：查校验层（第 2 课）、查设备扩展（第 6 课）都是同一套思路。

## 踩坑记录

- **空指针不是默认值**：`ppEnabledExtensionNames` 配 `enabledExtensionCount = 0` 才是"不启用"；结构体 `{}` 初始化后其余字段是零，但显式写出来更清晰
- **`VK_MAKE_VERSION` 宏**：版本号打包成单个整数，`1.0.0` → `(1 << 22) | (0 << 12) | 0`，别手算

## 小结

> 实例是应用的 Vulkan "会话"；扩展是可选功能模块，窗口相关的由 GLFW 代劳申报；两段式枚举是 Vulkan C API 的基本功。至此程序能"连上"Vulkan 了——但它还不会说错话被抓包，下一课先装"体检医生"。
