# 第 11 课 · 渲染呈现与同步

> 对应源码：`lessons/11_hello_triangle.cpp`（本课为**练习课**：`drawFrame()` 留给你实现）
> 目标：理解一帧从申请画布到上屏的完整节拍，用同步对象防止流水线打架，画出第一个三角形。

## 11.1 mainLoop：无尽的帧循环

```cpp
void mainLoop() {
    while (!glfwWindowShouldClose(window)) {
        glfwPollEvents();     // 处理窗口消息（移动/关闭/输入）
        drawFrame();          // 画一帧
    }
    vkDeviceWaitIdle(device); // 退出前：等 GPU 把手头活干完（后面 cleanup 依赖它）
}
```

`vkDeviceWaitIdle` 不能省——cleanup 会销毁一堆对象，而 GPU 可能还拿着它们执行命令。

## 11.2 drawFrame：一帧的五个节拍

```
①acquire        ②wait+reset      ③录制           ④submit          ⑤present
向交换链申请   CPU 等本帧 fence  把这一帧的     命令+两个信号量  把画好的图
一张空闲图     清零，恢复录制    命令写进缓冲    一起交给队列     交给呈现引擎
```

### 节拍①：申请图像

```cpp
uint32_t imageIndex;
vkAcquireNextImageKHR(device, swapChain, UINT64_MAX,
    imageAvailableSemaphores[currentFrame],   // 申请到手 → signal 这个信号量
    VK_NULL_HANDLE, &imageIndex);
```

### 节拍②：CPU-GPU 同步（fence）

```cpp
vkWaitForFences(device, 1, &inFlightFences[currentFrame], VK_TRUE, UINT64_MAX);
vkResetFences(device, 1, &inFlightFences[currentFrame]);
```

fence 是**给 CPU 用的**："上一帧用这个帧槽提交的命令，GPU 干完没有？"干完才允许覆写它的命令缓冲——否则 CPU 录到一半 GPU 还在读。

### 节拍③：录制（第 10 课的流程）

reset → 以 `swapChainFramebuffers[imageIndex]` 为目标重新录制。

### 节拍④：提交（命令 + 信号量打包）

```cpp
VkSubmitInfo submitInfo{};
submitInfo.waitSemaphoreCount = 1;
submitInfo.pWaitSemaphores   = &imageAvailableSemaphores[currentFrame];  // 等图到手
submitInfo.pWaitDstStageMask = waitStages;   // 在"颜色附件输出"阶段等（之前可并行干活）
submitInfo.commandBufferCount = 1;
submitInfo.pCommandBuffers   = &commandBuffers[currentFrame];
submitInfo.signalSemaphoreCount = 1;
submitInfo.pSignalSemaphores = &renderFinishedSemaphores[currentFrame];  // 画完 signal

vkQueueSubmit(graphicsQueue, 1, &submitInfo, inFlightFences[currentFrame]);
```

### 节拍⑤：呈现

```cpp
presentInfo.waitSemaphoreCount = 1;
presentInfo.pWaitSemaphores = &renderFinishedSemaphores[currentFrame];  // 等画完
presentInfo.pSwapchains = &swapChain;
presentInfo.pImageIndices = &imageIndex;
vkQueuePresentKHR(presentQueue, &presentInfo);
```

## 11.3 同步对象：三种"红绿灯"

这是本课概念密度最高的部分，一张表说清：

| 对象 | 管谁 | 语义 | 本课角色 |
|---|---|---|---|
| **信号量 Semaphore** | GPU ↔ GPU | " GPU 的 A 工序完了，B 可以开始" | acquire→绘制、绘制→present 两条衔接 |
| **栅栏 Fence** | GPU → CPU | "GPU 活干完了，CPU 才能动" | 防止 CPU 覆写 GPU 还在用的命令缓冲 |
| **事件 Event** | 细粒度 | 命令流中间插桩 | 本课不用 |

为什么要 `imagesInFlight`（按**图像**记账的 fence）？因为帧槽（`currentFrame`，按 MAX_FRAMES_IN_FLIGHT 轮转）和交换链图（`imageIndex`，acquire 返回）**不是一一对应**——acquire 可能连续两次给同一张图（比如另一张还在上屏）。每张图记着"现在谁在用我"，换图主时先等旧主 fence。

### 帧槽轮转的意义

`MAX_FRAMES_IN_FLIGHT = 2`：CPU 最多比 GPU 领先 2 帧。领先太多没意义（输入延迟变高），太少则 GPU 干等 CPU。

## 11.4 出错与窗口变化

```cpp
if (result == VK_ERROR_OUT_OF_DATE_KHR) {   // 交换链和窗口对不上了（resize）
    recreateSwapChain();
} else if (result != VK_SUCCESS && result != VK_SUBOPTIMAL_KHR) {
    throw std::runtime_error("呈现失败");
}
```

`OUT_OF_DATE` 必须重建；`SUBOPTIMAL`（还能用但不匹配）可继续——教程统一选择也重建，简单稳妥。重建前 `vkDeviceWaitIdle`，等所有在飞命令落地再动交换链。

## 11.5 练习：自己画出这个三角形

本课的 `drawFrame()` 是空的——五步提示写在代码注释里，参考试图但别照抄：

1. **acquire**：调对函数，拿到 `imageIndex`，注意信号量参数的位置
2. **等 fence**：等的是"当前帧槽"的 fence，等完 reset 它
3. **检查这张图是否被别的帧槽占用**（`imagesInFlight`），占用则等它的 fence
4. **录制**：reset 命令缓冲，以 `swapChainFramebuffers[imageIndex]` 开 render pass，补上视口/裁剪/绑定管线/`vkCmdDraw(3,1,0,0)`，封卷
5. **提交 + present**：信号量"一到一离"别接反，fence 挂提交上

**验收标准**：窗口里一个红彤彤的三角形稳稳居中，校验层全程闭嘴。

> 卡住时的自查顺序：三角形没有 → 看 `vkCmdDraw` 录没录进去；有三角形但闪/花 → 查信号量配对；一 resize 就崩 → 查 `framebufferResized` 旗标和重建调用。参考实现见仓库提交 `b93dc16`。

## 踩坑记录

- **信号量不能给 CPU 用、fence 不能给 GPU 用**：这是规范层面的限制，不是性能建议。acquire 返回后 CPU 想确认图像可用？没有直接手段——靠下一课的 fence 间接保证
- **fence 忘记 reset**：`vkWaitForFences` 等一个已 signal 的 fence 立即返回，但**提交后 fence 保持 signal 态**，下帧不等直接过——必须 `vkResetFences` 才恢复等待能力
- **present 用了图形队列而不是呈现队列**：本教程两队列族是同一个，用哪个都能跑；真·双队列族平台上这是 bug

## 小结

> 一帧五节拍：申请图 → fence 守门 → 录制 → 信号量接力提交 → 呈现；帧槽轮转让 CPU 领先 GPU 两帧为限。第 1-10 课的所有对象在这一课拧成一股绳——跑通它的那一刻，Vulkan 的"显式"就不再是负担，而是你能逐行指认的流水线。恭喜，你现在是一个写过 Vulkan 渲染循环的人了。
