# 第 5 课 · 窗口表面

> 对应源码：`lessons/05_window_surface.cpp`
> 目标：创建 `VkSurfaceKHR`——把"渲染目的地"和具体窗口绑定；选卡标准升级：图形族之外还要"能呈现"。

## 5.1 VkSurfaceKHR：平台无关的"渲染目的地"

Vulkan 核心 API 刻意不碰窗口系统（这是它能跨平台的原因）。但渲染总要画到**某个具体的窗口**上，这个"目的地"就是表面（Surface）：

```
你的三角形 → Vulkan 渲染 → VkImage（交换链的图）→ VkSurfaceKHR → 显示在窗口上
                                                    ↑
                              平台相关：Win32 是 HWND，
                              交给 GLFW 代办创建
```

表面和实例绑定（不是设备！）——同一实例下可以先有表面，后选设备。

## 5.2 为什么创建表面也交给 GLFW

创建 Win32 表面的本质是填一个 `VkWin32SurfaceCreateInfoKHR`（里面有 `HWND` 等 Win32 句柄）再调用对应函数。但写出这段代码，你的程序就和 Windows 焊死了。

```cpp
// GLFW 代办：一行代码，跨平台
if (glfwCreateWindowSurface(instance, window, nullptr, &surface) != VK_SUCCESS) {
    throw std::runtime_error("创建窗口表面失败");
}
```

GLFW 内部做的事：Windows 上调 `vkCreateWin32SurfaceKHR`、X11 上调 `vkCreateXlibSurfaceKHR`、macOS 上调 Metal 桥接……你读 GLFW 源码会看到一版"按平台分发表"的实现。这也正是第 2 课"扩展函数动态加载"的真实生产场景。

## 5.3 呈现能力：队列族 × 表面的配对属性

第 3 课找到了图形族，但"能渲染"不等于"能显示"——能不能向**这个表面**呈现，要逐个族查询：

```cpp
VkBool32 presentSupport = false;
vkGetPhysicalDeviceSurfaceSupportKHR(device, i, surface, &presentSupport);
if (presentSupport) {
    indices.presentFamily = i;
}
```

注意查询的签名：设备、**族下标**、**表面**三个都要——呈现能力是"这对组合"的属性，不是族自身的固有属性。

## 5.4 QueueFamilyIndices 升级：双 optional

```cpp
struct QueueFamilyIndices {
    std::optional<uint32_t> graphicsFamily;
    std::optional<uint32_t> presentFamily;   // 本课新增

    bool isComplete() {
        return graphicsFamily.has_value() && presentFamily.has_value();
    }
};
```

两个族**可能是同一个**（常见情况：同族既支持图形又支持呈现），也可能不同（某些双显卡笔记本上，渲染走独显、显示走核显）。本教程为简单起见后续都按"同一个"用，第 6 课创建交换链时会看到二者的差异点。

## 踩坑记录

- **表面属于实例，不属于设备**：销毁顺序别搞反——第 4 课的队列、第 6 课的交换链都跟设备走，表面跟实例走，在 `vkDestroyInstance` 之前销毁即可
- **`glfwCreateWindowSurface` 要求窗口以 `GLFW_NO_API` 创建**：`glfwWindowHint(GLFW_CLIENT_API, GLFW_NO_API)` 在 `initWindow` 里已做，漏了这步 GLFW 会报错

## 小结

> 表面是渲染目的地与窗口的桥，平台相关的创建交给 GLFW；呈现能力要按"族 × 表面"组合查询。选卡标准现在有两条：有图形族、有呈现族。画布挂点有了，下一课去领"纸"——交换链。
