# 第 6 课 · 交换链

> 对应源码：`lessons/06_swap_chain.cpp`
> 目标：创建交换链——拿到一组轮流上屏的 `VkImage`，并理解"为什么渲染不直接画到窗口"。

## 6.1 为什么需要交换链

朴素的想法是"渲染直接写进窗口的显存"。这会有灾难性的后果：

```
显示器正在读取 ──→ 你同时写入  ──→ 屏幕上半部分是旧帧、下半部分是新帧
   第 N 帧            第 N+1 帧         = 画面撕裂（tearing）
```

交换链的解法：**准备多张图，轮换使用**。

```
时间轴 →
图像A: [渲染]→[等待呈现]→[上屏] ──────────────────→ [回收，渲染下一帧]
图像B: ────── [渲染]→[等待呈现]→[上屏] ────────────→ [回收]
图像C: ──────────────────── [渲染]→[等待呈现]→[上屏] → ...
```

程序往"空闲的那张"上画，画完交给呈现队列；显示器取走上屏的那张时，其余的在排队。交换链本质是一组 `VkImage` 的**循环队列**——注意图不是你创建的，是交换链内部创建、你"借用"的。

## 6.2 先查能力：三张表

创建前要摸清这个"表面 + 设备"组合支持什么：

```cpp
struct SwapChainSupportDetails {
    VkSurfaceCapabilitiesKHR capabilities;            // ① 数量/尺寸范围
    std::vector<VkSurfaceFormatKHR> formats;          // ② 像素格式 × 色彩空间
    std::vector<VkPresentModeKHR> presentModes;       // ③ 呈现模式（排队策略）
};
```

三段查询全是两段式枚举（第 1 课的老朋友）。然后三个"三选一"：

### 选格式（formats）

```cpp
// 首选：B8G8R8A8 + SRGB 色彩空间（最常见的屏幕组合）
for (const auto& availableFormat : formats) {
    if (availableFormat.format == VK_FORMAT_B8G8R8A8_SRGB &&
        availableFormat.colorSpace == VK_COLOR_SPACE_SRGB_NONLINEAR_KHR) {
        return availableFormat;
    }
}
return formats[0];   // 没有心仪的就用第一个——Vulkan 保证至少有一个
```

### 选呈现模式（presentModes）

| 模式 | 行为 | 体验 |
|---|---|---|
| `IMMEDIATE` | 画完立刻上屏 | 可能撕裂，延迟最低 |
| `FIFO` | 排队，显示器取走才补位（**永远可用**） | 类似垂直同步 |
| `FIFO_RELAXED` | FIFO 变体 | 低帧率时少卡顿 |
| `MAILBOX` | FIFO + 队列只留最新 | **本教程首选**：不撕裂、低延迟 |

首选 `MAILBOX`，退而求其次 `FIFO`（规范保证它必然存在）。

### 选分辨率（extent）

通常 `capabilities.currentExtent` 直接就是窗口尺寸，照抄即可；遇到 `0xFFFFFFFF`（特殊值，意思"你看着办"）就用 `std::clamp` 夹在 `minImageExtent` 和 `maxImageExtent` 之间。

## 6.3 创建交换链

```cpp
VkSwapchainCreateInfoKHR createInfo{};
createInfo.surface = surface;
createInfo.minImageCount = capabilities.minImageCount + 1;   // 宁可多一张，不要刚好卡下限
createInfo.imageFormat = surfaceFormat.format;
createInfo.imageExtent = extent;
createInfo.imageArrayLayers = 1;
createInfo.imageUsage = VK_IMAGE_USAGE_COLOR_ATTACHMENT_BIT;  // 当颜色画笔画
createInfo.imageSharingMode = VK_SHARING_MODE_EXCLUSIVE;      // 本课假设图形族=呈现族
// …呈现模式、裁剪、旧链引用等
```

`minImageCount + 1` 的经验：下限意味着"任何一张被占用你就干等"，多一张换余量。

## 6.4 取出交换链的图

```cpp
vkGetSwapchainImagesKHR(device, swapChain, &imageCount, nullptr);       // ① 问数量
swapChainImages.resize(imageCount);
vkGetSwapchainImagesKHR(device, swapChain, &imageCount, swapChainImages.data());
```

数量以驱动实际给的为准——**你请求 3 张，可能给你 4 张**，一切以 `imageCount` 实收为准。这些 `VkImage` 不需要你销毁（随交换链生灭），但每张都要配视图——下一课。

## 6.5 选卡门槛再 +1：设备扩展

`vkCreateSwapchainKHR` 是**设备扩展**函数（不是实例扩展！）。所以第 3 课的 `isDeviceSuitable` 要加一条：设备必须支持 `VK_KHR_swapchain` 扩展，用"查需求 ⊆ 全集"的老套路。

同时创建设备时要在 `VkDeviceCreateInfo` 里启用它——这又是"声明 + 动态加载"的组合拳：

```cpp
auto func = (PFN_vkCreateSwapchainKHR)vkGetInstanceProcAddr(instance, "vkCreateSwapchainKHR");
```

## 踩坑记录

- **实例扩展 ≠ 设备扩展**：`glfwGetRequiredInstanceExtensions` 给的是实例级；`VK_KHR_swapchain` 是设备级，两条通道都要走
- **`VK_SHARING_MODE_EXCLUSIVE` 的前提**：图形族 ≠ 呈现族时这个模式不安全（并发访问要所有权转移），本教程按同族处理，后面创建逻辑设备时会有对应的并发模式分支
- **收到 `VK_ERROR_OUT_OF_DATE_KHR`**：交换链和窗口尺寸不同步了（用户拖了窗口），需要重建——第 11 课处理

## 小结

> 交换链 = 一组循环上屏的 VkImage，解决撕裂；创建前三查：能力/格式/呈现模式，三个三选一；图是借来的不用销毁。至此"纸"领到了，但它还不能进管线——下一课给每张纸配"读法"。
