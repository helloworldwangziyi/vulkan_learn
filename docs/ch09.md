# 第 9 课 · 帧缓冲

> 对应源码：`lessons/09_framebuffers.cpp`
> 目标：创建帧缓冲——把"图纸（渲染通道）"和"画布（图像视图）"装订成可以真正落笔的对象。

## 9.1 图纸与画布的关系

前 8 课攒下了两类东西：

- **渲染通道**：图纸——"要几个附件、每个怎么用（清不清/留不留）"
- **图像视图**：画布坯子——交换链每张图配了一个"读法"

帧缓冲（Framebuffer）就是按图纸把具体画布绑上去：

```
渲染通道图纸: "我需要 1 块颜色附件"
                    │
                    ▼
帧缓冲:  把 swapChainImageViews[0] 绑上去   ← 一本成册
帧缓冲:  把 swapChainImageViews[1] 绑上去   ← 又一本
帧缓冲:  把 swapChainImageViews[2] 绑上去   ← 又一本
```

```cpp
VkFramebufferCreateInfo framebufferInfo{};
framebufferInfo.renderPass = renderPass;               // 按哪张图纸
framebufferInfo.attachmentCount = 1;
framebufferInfo.pAttachments = &swapChainImageViews[i]; // 用哪张图
framebufferInfo.width  = swapChainExtent.width;
framebufferInfo.height = swapChainExtent.height;
```

## 9.2 几个交换链图，就建几个帧缓冲

```cpp
swapChainFramebuffers.resize(swapChainImageViews.size());
for (size_t i = 0; i < swapChainImageViews.size(); i++) { /* 逐个创建 */ }
```

原因在渲染时序：每一帧，程序先向交换链**申请一张空闲图**（`vkAcquireNextImageKHR` 返回下标），然后用**对应的那个帧缓冲**录制渲染命令。图和帧缓冲一一对应，多一个都不行。

## 9.3 帧缓冲本身很廉价

注意它**不分配像素内存**——真正的显存是交换链图（第 6 课）持有的。帧缓冲只是一把"句柄的集合"：图纸引用 + 视图引用 + 尺寸。所以这个对象创建/销毁都很便宜；后面深度缓冲一课，也只是往这个集合里多塞一个附件引用。

与之对应，尺寸必须和绑定的图一致，且**不能大于渲染区域**。窗口 resize 后交换链重建、图换了，帧缓冲必须跟着重建（它比视图更短命——引用的视图死了它先死）。

## 踩坑记录

- **帧缓冲数量 ≠ 交换链图数量**：数量不一致会在渲染时拿错画布，症状是偶尔花屏或校验层抱怨帧缓冲与图像不匹配
- **销毁顺序**：帧缓冲 → 图像视图 → 交换链，严格从引用方到被引用方

## 小结

> 帧缓冲 = 渲染通道图纸 + 具体图像视图的装订本；一图一本、薄如索引。至此"纸、读法、笔、装订"俱全——下一课开始写"作画指令"：命令缓冲。
