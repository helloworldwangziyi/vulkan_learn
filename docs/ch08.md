# 第 8 课 · 图形管线

> 对应源码：`lessons/08_graphics_pipeline.cpp`
> 目标：装配 Vulkan 图形管线——全教程最厚的一课，但拆开后每一站都有明确的职责。

## 8.0 全景：一条单向流水线

```
顶点数据 → [顶点着色器] → 图元装配 → 光栅化 → [片元着色器] → 颜色混合 → 颜色附件
              ↑可编程           ↑固定          ↑固定           ↑可编程      ↑固定(可配)
```

方括号里是你写代码的（着色器），其余是硬件固定功能、只能配置不能编程。Vulkan 要求把整条流水线的**全部配置**一次性装进 `VkPipeline` 对象——创建后不可改（immutable），想换任何状态就重建。

> 和 OpenGL 对比：GL 是"每帧每步都设状态"（`glViewport`、`glBlendFunc` 随时调），Vulkan 是"签约时一次定终身"。前者灵活但驱动要在运行时猜你的意图，后者把验证全部前置——这正是 Vulkan 性能的根基。

## 8.1 渲染通道先行：管线要引用它

创建管线前先创建渲染通道（Render Pass），因为管线装配的最后一个参数就是"按哪张图纸画"。渲染通道声明渲染目标（**附件**，attachment）的用法：

```cpp
VkAttachmentDescription colorAttachment{};
colorAttachment.format = swapChainImageFormat;
colorAttachment.samples = VK_SAMPLE_COUNT_1_BIT;           // 单采样
colorAttachment.loadOp  = VK_ATTACHMENT_LOAD_OP_CLEAR;     // 开工前：清屏
colorAttachment.storeOp = VK_ATTACHMENT_STORE_OP_STORE;    // 完工后：保留（要呈现）
colorAttachment.initialLayout = VK_IMAGE_LAYOUT_UNDEFINED;     // 不关心之前内容
colorAttachment.finalLayout   = VK_IMAGE_LAYOUT_PRESENT_SRC_KHR; // 最终要能呈现
```

两个必懂字段：

- **loadOp**：这一帧开始前，画布上的旧内容怎么办？`CLEAR` = 清屏重来
- **storeOp**：画完后结果保不保留？要呈现自然是 `STORE`

附件只是"图纸"不是"实物"——第 9 课的帧缓冲才把真正的图绑上来。

### 子通道与依赖

```cpp
VkSubpassDescription subpass{};
subpass.pipelineBindPoint = VK_PIPELINE_BIND_POINT_GRAPHICS;
subpass.colorAttachmentCount = 1;
subpass.pColorAttachments = &colorAttachmentRef;
```

子通道（subpass）是渲染通道内的渲染步骤，引用附件的"角色位"。配套的**子通道依赖**解决时序：交换链图像刚从"呈现"状态转来，本帧的写入必须等它空闲——`srcStage`/`dstStage` 的掩码组合就是这份"等待指令"。本课是皮毛，后续多附件渲染会加深理解。

## 8.2 着色器：SPIR-V 离线编译

Vulkan 不认识 GLSL 源码，只认 **SPIR-V** 字节码——编译期用 SDK 自带的 `glslc` 离线完成：

```bash
glslc shader.vert -o vert.spv
glslc shader.frag -o frag.spv
```

运行时读字节码 → 创建着色器模块 → 装配进管线：

```cpp
VkPipelineShaderStageCreateInfo vertShaderStageInfo{};
vertShaderStageInfo.stage = VK_SHADER_STAGE_VERTEX_BIT;
vertShaderStageInfo.module = vertShaderModule;
vertShaderStageInfo.pName = "main";   // 入口函数名
```

本课的着色器刻意最简：顶点着色器写死三个点的坐标，片元着色器输出固定红色——数据通路（顶点属性、uniform）是后面课程的事。

## 8.3 逐站装配

### ① 顶点输入：现在为空

```cpp
vertexInputInfo.vertexBindingDescriptionCount = 0;
vertexInputInfo.vertexAttributeDescriptionCount = 0;
```

顶点数据从缓冲区进管线要两份声明（绑定描述 + 属性描述），本课没用顶点缓冲，全零。

### ② 输入装配：顶点怎么连成三角形

```cpp
inputAssembly.topology = VK_PRIMITIVE_TOPOLOGY_TRIANGLE_LIST;
inputAssembly.primitiveRestartEnable = VK_FALSE;
```

topology 回答"顶点流怎么切块"（`TRIANGLE_LIST` = 每 3 个顶点独立成三角形；还有 `TRIANGLE_STRIP` 蛇形接力、`TRIANGLE_FAN` 折扇共顶点等）。工程上最常用的是 `TRIANGLE_LIST + 索引缓冲`——自由编组、方便去重。`primitiveRestartEnable` 配合索引缓冲，用特殊下标值切断图元串，本课用不到。

### ③ 视口与裁剪：只登记，不填值

```cpp
viewportState.viewportCount = 1;
viewportState.scissorCount = 1;
```

只有数量没有数值——因为下一步把它俩登记为**动态状态**，具体值留到录制命令缓冲时给（见 8.4）。

- **视口**：NDC(-1~1) → 屏幕坐标的映射（画多大、画在哪）
- **裁剪**：矩形外的片元直接丢弃（画什么形状的区域）

### ④ 光栅化

```cpp
rasterizer.polygonMode = VK_POLYGON_MODE_FILL;   // 填充（线框/点模式也是它）
rasterizer.cullMode = VK_CULL_MODE_BACK_BIT;     // 剔除背面
rasterizer.frontFace = VK_FRONT_FACE_CLOCKWISE;  // 本课 NDC 顺时针为正面
rasterizer.lineWidth = 1.0f;
```

`cullMode`/`frontFace` 是一对：告诉 GPU 三角形"哪面算正面"、要不要省掉背面。本课选 `CLOCKWISE` 而非教程默认的逆时针——因为后续投影矩阵的 Y 翻转会改变绕向，提前对齐（第 15 课会彻底说清）。**绕序约定和顶点顺序不匹配时，三角形会被整体剔除**—— symptoms 就是"窗口全黑，校验层一声不吭"，是新手最常见的天坑之一。

### ⑤ 多重采样：关闭

`sampleShadingEnable = false`、`rasterizationSamples = 1`——抗锯齿是后面 MSAA 一课的专属内容。

### ⑥ 颜色混合：新像素与旧像素怎么相处

```cpp
colorBlendAttachment.blendEnable = VK_FALSE;              // 不做透明混合：直接覆盖
colorBlendAttachment.colorWriteMask = R|G|B|A;            // 四个通道都允许写
```

注意区分两个容易混淆的"混合"：

| | 顶点插值 | 颜色混合（本处） |
|---|---|---|
| 混什么 | 三角形**内部**：三个顶点颜色的加权渐变 | 新片元与附件里**旧像素**的叠加 |
| 谁做 | 光栅化器自动做 | 管线这里配置 |

`blendEnable = false` 即"新颜色直接盖掉旧的"。全局结构里 `logicOpEnable = false` 是声明走 blend 路线而非逻辑位运算路线（后者如今几乎只在老 CAD 软件见到）。

### ⑦ 动态状态：易变的赶出管线

```cpp
std::vector<VkDynamicState> dynamicStates = {
    VK_DYNAMIC_STATE_VIEWPORT,
    VK_DYNAMIC_STATE_SCISSOR
};
```

管线创建后不可改，但视口尺寸天然爱变（窗口能拖）。动态状态是 Vulkan 给的折中：**创建管线时登记"这两格留空"，录制命令时用 `vkCmdSetViewport/Scissor` 现填**。易变的赶进命令缓冲，管线终身只建一次。

### ⑧ 管线布局：着色器的资源申报单

```cpp
pipelineLayoutInfo.setLayoutCount = 0;
pipelineLayoutInfo.pushConstantRangeCount = 0;
```

它不持有任何资源，只是**清单**："本管线着色器要用哪些资源集合、哪些 push constant"。创建管线时驱动核对清单与着色器字节码里的声明是否一致。本课着色器自给自足（不读任何外部数据），申报单空白——但**申报动作省不掉**，空白申报单也是申报单。

## 8.4 为什么视口要"动态"

如果把视口写死在管线里：窗口一 resize，交换链和帧缓冲都重建了，管线还照着老尺寸把画面画在一个角落（多出的区域只有清屏色）。正确处理要把管线也塞进重建清单——而管线是 Vulkan 里最贵的对象之一。动态状态让 resize 的重建链条短了一大截：**结构照常重建，最贵的管线纹丝不动，新尺寸由每帧录制命令时自然注入**。

## 8.5 装配与销毁

十余个局部结构最终汇入：

```cpp
pipelineInfo.stageCount = 2;
pipelineInfo.pStages = shaderStages;
// …前面所有站的指针
pipelineInfo.renderPass = renderPass;   // 按哪张图纸
pipelineInfo.layout = pipelineLayout;

vkCreateGraphicsPipelines(device, VK_NULL_HANDLE, 1, &pipelineInfo, nullptr, &graphicsPipeline);
```

注意复数 `Pipelines` + 数组参数——一次可建多条，便于引擎预编译整套管线变体。用完别忘了销毁两个着色器模块（**装配进管线后它们就没用了**）和管线本身。

## 踩坑记录

- **三角形消失但校验层安静**：九成是 `frontFace` 与顶点绕序不匹配被背面剔除，或顶点坐标全在 NDC 之外——先查这两个
- **着色器模块要及时销毁**：它们只是"源代码容器"，装配完管线即可 `vkDestroyShaderModule`
- **`shaders/build.cmd` 忘了重跑**：改了 `.vert/.frag` 但没重新生成 `.spv`，运行的是旧着色器——症状是"我明明改了怎么没变"

## 小结

> 管线是不可变状态机：渲染通道定图纸，十余个固定功能站逐站装配，着色器离线编译装入，易变的视口登记为动态状态，管线布局做资源申报。笔造好了，下一课把"图纸 + 纸"装订成可以真正落笔的成品画布——帧缓冲。
